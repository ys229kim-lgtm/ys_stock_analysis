# 뉴스 수집·사건 분석 Agent 설계서

> **문서 목적**: Claude Code에서 구현 시 참조할 계획서  
> **작성 기준**: 국내+해외(선택적) 뉴스 / 최근 1~2년 / 이슈 단위 클러스터링 / 미래 추진계획 포함  
> **산출물 포맷**: 수집 원본 + 마크다운(.md) + Word 문서(.docx)  
> **출력 폴더**: 독립 프로젝트 폴더 (`{날짜}_{기업명}_news/`)  
> **설계서 버전**: v1.1 (인터뷰 기반 업데이트)

---

## 1. 작업 컨텍스트 문서

### 1.1 배경 및 목적

주식 분석 멀티에이전트 시스템의 **세 번째 서브에이전트**로, 최근 1~2년간 기업 관련 국내외 뉴스를 수집하고 긍정적·부정적 사건을 구조화 분석하며 기업의 미래 추진 계획을 추출한다. 재무 데이터(DART agent)·증권사 시각(Telegram agent)과 달리 **실제 발생한 사건과 공개된 경영 계획**이라는 팩트 레이어를 담당한다.

**최종 소비자:** 개인 투자자 (매수/매도 전 최종 점검 도구). 현재 진행 중인 리스크와 사건 연속성이 핵심 가치.

**이 에이전트가 답하는 핵심 질문:**
- 최근 1~2년간 이 기업에 실제로 어떤 일이 있었는가? (긍정/부정 사건 목록)
- 지금 해소되지 않은 리스크(소송·규제·실적 저하)는 무엇인가?
- 기업이 공개적으로 선언한 미래 전략·투자 계획·사업 목표는 무엇인가?

**오케스트레이터 통합:** 기존 financial-analysis-agent·telegram-report-agent와 함께 **3번째 병렬 에이전트**로 실행. 오케스트레이터(C:/claude/stock/CLAUDE.md) 업데이트 필요.

**뉴스 수집 도구:** 외부 Python 스크립트 없이 **Firecrawl MCP를 에이전트가 직접 호출**하여 수집.
단, **Firecrawl 무료 사용량/크레딧 초과 시** 검색은 내장 `WebSearch`, 본문 추출은 `mcp__crawl4ai-mcp__scrape`(로컬 브라우저 기반, 사용량 무제한)로 **자동 fallback**한다. (상세 정책: CLAUDE.md Step 1 도구 정책)

### 1.2 입출력 정의

| 구분 | 항목 | 설명 |
|------|------|------|
| **입력** | 기업명 (필수) | 검색 키워드 기본값 (예: 삼성전자) |
| **입력** | 영문 기업명 (선택) | 해외 뉴스 선택적 강화용 (예: Samsung Electronics) |
| **입력** | 종목코드 (선택) | 보조 검색 키워드 |
| **입력** | 수집 기간 (선택) | 미입력 시 최근 2년 자동 적용 |
| **입력** | `--reuse` 플래그 (선택) | 이전 raw_articles JSON 재활용 후 신규 기사만 추가 수집 |
| **출력** | 출력 폴더 | `./{날짜}_{기업명}_news/` (없으면 자동 생성) |
| **출력** | 수집 원본 JSON | `./{날짜}_{기업명}_news/raw/raw_articles_{날짜}_{기업명}.json` |
| **출력** | 클러스터 데이터 JSON | `./{날짜}_{기업명}_news/output/clusters_{날짜}_{기업명}.json` |
| **출력** | 분석 구조화 데이터 JSON | `./{날짜}_{기업명}_news/output/analysis_{날짜}_{기업명}.json` |
| **출력** | 분석 마크다운 리포트 | `./{날짜}_{기업명}_news/output/report_{날짜}_{기업명}.md` |
| **출력** | 분석 Word 리포트 | `./{날짜}_{기업명}_news/output/report_{날짜}_{기업명}.docx` |

### 1.3 분석 범위

**수집 소스:**

| 소스 유형 | 대상 | 수집 방법 | 우선순위 |
|----------|------|----------|---------|
| 국내 뉴스 (일반 웹) | 네이버, 다음, 주요 언론사 자연 유입 | Firecrawl search (한국어 쿼리) | **필수** |
| 해외 뉴스 | Reuters, Bloomberg, FT, WSJ, CNBC | Firecrawl search (영문 쿼리) | **선택적 강화** |

> **해외 뉴스 정책:** Bloomberg·FT·WSJ 등 주요 해외 언론은 사실상 페이월로 스니펫(헤드라인+2~3문장)만 수집된다. 해외 뉴스는 "국내 사건이 해외에서도 보도됐는지 여부 확인"을 목적으로 하며, 수집 실패 또는 0건이어도 분석을 진행한다. 리포트에는 해외 커버리지 부재를 명시한다.

**수집 기간:** 실행일로부터 최대 2년 이전 ~ 현재 (기본값)

**분석 4대 영역:**

| 영역 | 내용 |
|------|------|
| 긍정 사건 | 수주·계약·실적 호조·신사업 성과·파트너십·수상 등 |
| 부정 사건 | 소송·제재·실적 부진·인력 감축·사고·규제 리스크 등 (**지속 여부** 강조 표시) |
| 미래 추진 계획 | 투자 계획·신사업 진출·M&A·R&D 로드맵·목표 선언 등 |
| 이슈 패턴 | 반복 등장 테마, 시계열 흐름, 사건 간 연관성 |

### 1.4 주요 제약조건

- Firecrawl search 1회 결과는 5~20건 수준 → 6가지 쿼리 유형으로 다양성 확보
- 수집량 목표(최소 20건·200건 상한 등) 수치는 **실제 테스트 후 조정** — 구현 시 확정 값 기재
- 페이월 차단 기사 → 스니펫만 활용, 메타데이터에 `paywall: true` 표기
- 국내외 뉴스 혼재 → 언어 감지 후 분리 처리, 최종 리포트는 한국어로 통합
- 동일 이슈 클러스터링은 LLM 판단 기반 (temperature=0 설정) → 오분류 가능성 있음
- 미래 추진 계획은 **공개 발표 기반**만 수집 (추측성 기사 배제)
- 진행 중인 사건(소송 등)의 단계 변화는 Step 5 서술에서 처리 (JSON 구조 변경 없음)

### 1.5 용어 정의

| 용어 | 정의 |
|------|------|
| 이슈 클러스터 | 동일 사건/주제를 다루는 복수 기사의 묶음 |
| 대표 기사 | 클러스터 내 가장 정보량이 많은 기사 1건 |
| 사건 타임라인 | 긍정/부정 사건을 날짜 순서로 배열한 연표 |
| 미래 추진 계획 | 기업이 공식 발표한 향후 전략·투자·목표 (IR, 보도자료, CEO 발언 포함) |
| 중요도 스코어 | 언론사 신뢰도 × 기사 길이 × 키워드 밀도를 종합한 기사 우선순위 점수 |
| ongoing 리스크 | 가장 최근 기사에서 해소가 확인되지 않은 부정 사건 |
| reuse 모드 | `--reuse` 플래그로 실행 시, 이전 raw_articles를 재활용하고 신규 기사만 추가 수집 |

## 2. 워크플로우 정의

### 2.1 전체 흐름

```
[입력: 기업명 + 영문명(선택) + 종목코드(선택) + --reuse(선택)]
        │
        ▼
[Step 0] 출력 폴더 생성 (setup_dirs.py)
   ./{날짜}_{기업명}_news/ 폴더 및 하위 구조 자동 생성
        │
        ▼
[Step 1] 뉴스 수집
   ▸ --reuse 있음: glob으로 *_{기업명}_news 패턴 탐색 → 가장 최근 폴더의
     raw_articles JSON 재활용 → 마지막 수집일 이후 신규 기사만 Firecrawl 추가 수집
   ▸ --reuse 없음: Firecrawl MCP 직접 호출 (국내 필수 + 해외 선택적)
   → raw_articles_{날짜}_{기업명}.json 저장
        │
        ▼
[Step 2] 전처리 및 중요도 필터링 (preprocess.py)
   URL 기반 중복 제거, 언어 감지, 중요도 스코어 계산, 상위 필터링
        │
        ▼
[Step 3] 이슈 클러스터링 (LLM, temperature=0)
   유사 기사 묶기 → 클러스터별 대표 기사 선정
   → clusters_{날짜}_{기업명}.json 저장
        │
        ▼
[Step 4] 사건별 LLM 구조화 분석
   클러스터 단위로 사건 분류·분석
   → 긍정/부정/미래계획 태깅, 중요도·영향 범위 평가, ongoing 여부 판단
   → analysis_{날짜}_{기업명}.json 저장
        │
        ▼
[Step 5] LLM 종합 분석
   전체 사건 교차 분석
   → 타임라인 구성, ongoing 리스크 강조, 패턴 도출, 미래 계획 통합
        │
        ▼
[Step 6] 문서 생성 (generate_md.py + generate_docx.py)
   분석 결과 → md + docx 생성 (python-docx 사용, 테이블 기반)
        │
        ▼
[출력: ./{날짜}_{기업명}_news/ 내 전체 산출물]
```

### 2.2 단계별 상세 정의

---

#### Step 0: 출력 폴더 생성

**처리 주체:** 스크립트 (`setup_dirs.py`)

**생성 폴더 구조:**
```
./{날짜}_{기업명}_news/
  ├── /raw/           # 수집 원본 JSON
  ├── /fetched/       # 전문 fetch 성공한 기사 본문 텍스트
  └── /output/        # 분석 결과 산출물
```

**성공 기준:** 3개 폴더 모두 생성 확인  
**실패 처리:** 권한 오류 → 에스컬레이션

---

#### Step 1: 뉴스 수집

**처리 주체:** 에이전트가 **Firecrawl MCP 직접 호출** (collect_news.py 없음)

**reuse 모드 동작:**
```
--reuse 플래그 있음?
  ├─ YES →
  │   1. C:/claude/stock/ 에서 *_{기업명}_news 패턴 폴더를 glob으로 수집
  │   2. 수정일 기준 가장 최근 폴더 선택
  │   3. 해당 폴더의 raw_articles JSON 로드
  │   4. 마지막 기사 날짜 이후 기간만 신규 수집 (아래 쿼리 구성 적용)
  │   5. 신규 기사를 기존 목록에 병합, 중복 제거
  └─ NO → 전체 수집 (아래 쿼리 구성 적용)
```

**검색 쿼리 구성 (Firecrawl search 호출):**

| 검색 유형 | 쿼리 예시 | 비고 |
|----------|----------|------|
| 국내 기본 | `삼성전자 뉴스 2024 2025` | 연도 명시로 기간 필터 |
| 국내 사건 | `삼성전자 소송 계약 실적 제재` | 사건성 키워드 추가 |
| 국내 전략 | `삼성전자 투자계획 신사업 로드맵 M&A` | 미래 계획 타깃 |
| 해외 기본 | `Samsung Electronics news 2024 2025` | 영문명 사용, 선택적 실행 |
| 해외 사건 | `Samsung Electronics lawsuit contract earnings penalty` | 선택적 실행 |
| 해외 전략 | `Samsung Electronics investment strategy roadmap` | 선택적 실행 |

> **해외 쿼리 정책:** 영문명이 제공된 경우에만 실행. 0건이어도 오류가 아님.

**수집 항목 (기사당):**
- 제목, URL, 언론사명, 발행일, 스니펫(요약문)
- 본문 전문 (Firecrawl scrape 성공 시 /fetched/ 저장), 언어 코드(ko/en)
- 페이월 여부 플래그

**분기조건:**
```
Firecrawl fetch 시도 → 성공?
  ├─ YES → 본문 전문 저장 (/fetched/)
  └─ NO (페이월/차단) → 스니펫만 저장, paywall: true 플래그

수집 건수 = 0건?
  └─ 에스컬레이션 (키워드 또는 기간 확인 요청)
```

**성공 기준:** *(테스트 후 확정 — 아래는 초기 목표치)*
- 국내 기사 최소 10건 이상
- 전체 수집 최소 20건 이상

**실패 처리:**
- Firecrawl API 오류 → 재시도 3회
- 해외 검색만 0건 → 국내 기사만으로 진행, 리포트에 해외 데이터 부재 명시

---

#### Step 2: 전처리 및 중요도 필터링

**처리 주체:** 스크립트 (`preprocess.py`)

**수행 작업:**
- URL 기반 중복 제거 (동일 URL 복수 수집 제거)
- 유사 제목 중복 제거 (제목 문자열 유사도 85% 이상 → 최신 기사 1건 유지)
- 언어 감지 (`langdetect` 라이브러리): `ko` / `en` / `other` 분류
- 기간 필터: 수집 기간 외 기사 제거
- **중요도 스코어 계산** (상위 필터링 임계값은 테스트 후 확정):

| 항목 | 가중치 | 평가 기준 |
|------|--------|----------|
| 언론사 신뢰도 | 40% | 직접 작성한 고정 티어 목록 기반 (references/media_tier_list.md) |
| 본문 길이 | 30% | 전문 fetch 성공 기사 우대, 스니펫만인 경우 하향 |
| 제목 키워드 밀도 | 30% | 기업명 + 사건성 키워드 포함 여부 |

- 결과를 `raw_articles_{날짜}_{기업명}.json`으로 저장

**언론사 신뢰도 티어 관리:** `references/media_tier_list.md`에 초기 1회 직접 작성. 수동 업데이트. 목록에 없는 언론사는 Tier 3(하위) 처리.

**성공 기준:** *(테스트 후 확정)*
- 필터링 후 최소 20건 잔존
- 국내/해외 각각 1건 이상 존재 (해외 0건은 허용, 리포트에 명시)

**실패 처리:** 필터링 후 20건 미만 → 기간을 자동으로 최대 2년으로 확장 후 재수집 1회 시도

---

#### Step 3: 이슈 클러스터링

**처리 주체:** 에이전트 직접 수행 (LLM, **temperature=0**)

**클러스터링 기준:**
- 동일 사건·계약·발표·소송 등을 다루는 기사는 하나의 클러스터로 묶음
- 동일 사건이 시간에 걸쳐 여러 기사로 보도된 경우(예: 협상 개시 → 계약 확정 → 납품 개시) 하나의 클러스터로 묶음 — 단계 변화는 Step 5 서술에서 기술
- 클러스터 내 **대표 기사** 1건 선정 기준: 본문 길이 가장 길거나 최초 보도 기사
- 클러스터당 최소 1건, 최대 제한 없음

**각 클러스터에 부여할 메타데이터:**
```json
{
  "cluster_id": "C001",
  "cluster_title": "HBM3E 엔비디아 공급 계약 체결",
  "article_count": 7,
  "date_range": { "first": "2025-03-10", "last": "2025-03-18" },
  "representative_article": "기사 URL 또는 파일명",
  "member_articles": ["URL1", "URL2"],
  "languages": ["ko", "en"]
}
```

**성공 기준 (LLM 자기 검증):**
- 클러스터 수가 전체 기사 수의 20% 이상 (지나친 분리 방지)
- 각 클러스터에 `cluster_title`이 명시적으로 존재
- 무관 기사(기업 언급 미미)는 `irrelevant` 클러스터로 분리

**실패 처리:**
- 클러스터 수 < 전체 기사 수의 20% → 재클러스터링 1회
- 전체 기사가 1개 클러스터로 묶이는 경우 → 에스컬레이션

---

#### Step 4: 사건별 LLM 구조화 분석

**처리 주체:** 에이전트 직접 수행 (LLM, temperature=0)

**처리 단위:** 클러스터 1개 = 사건 1건  
**처리 방식:** 클러스터 순서대로 순차 처리, `analysis_{날짜}_{기업명}.json`에 누적

**각 클러스터에서 추출할 구조화 데이터:**

```json
{
  "cluster_id": "C001",
  "cluster_title": "HBM3E 엔비디아 공급 계약 체결",
  "event_date": "2025-03-10",
  "category": "positive | negative | future_plan | neutral",
  "sub_category": "계약/수주 | 실적 | 소송/제재 | 인사 | 투자계획 | 신사업 | 파트너십 | 사고/리스크 | 규제 | 기타",
  "summary": "사건 한 줄 요약 (50자 이내)",
  "detail": "사건 상세 설명 (200자 이내, 원문 기반)",
  "ongoing": true,
  "impact_scope": "단기 | 중기 | 장기",
  "impact_magnitude": "high | medium | low",
  "entities_involved": ["엔비디아", "HBM3E"],
  "financial_implications": "매출/이익/비용에 미치는 영향 (추정 가능 시)",
  "future_plan_details": {
    "target": "목표 내용",
    "timeline": "YYYY 또는 YYYY-MM 또는 '명시없음'",
    "investment_amount": 숫자 또는 null,
    "investment_unit": "억원 | 조원 | 억달러 | null"
  },
  "source_languages": ["ko", "en"],
  "confidence": "high | medium | low",
  "parse_failed": false
}
```

> **`ongoing` 필드 정의:** `category: negative` 또는 `future_plan`인 사건에서, 클러스터 내 **가장 최근 기사**에서 해소(완료·취하·종결)가 확인되지 않으면 `true`. 나머지는 `false`. 리포트에서 색상 강조에 사용됨.

**LLM 판단 지침:**
- `category` 분류 기준:
  - `positive`: 기업 가치·실적·경쟁력에 명확히 긍정적 영향
  - `negative`: 기업 가치·실적·경쟁력에 명확히 부정적 영향
  - `future_plan`: 기업이 공식 발표한 미래 계획·전략·목표 (결과 미확정)
  - `neutral`: 인사이동·조직 개편 등 방향성 불명확
- `future_plan_details`는 `category: future_plan`인 경우만 작성, 나머지는 null
- `ongoing` 판단: 최신 기사가 "완료", "취하", "종결", "해제" 등의 표현이 없으면 `true`
- 영향 규모(`impact_magnitude`) 판단 기준: 매출 대비 영향 추정치 또는 시장 반응 규모
- 추측성 내용은 `detail`에 포함 금지, 기사 원문 기반 팩트만 작성

**성공 기준 (LLM 자기 검증):**
- 필수 필드 (`cluster_id`, `category`, `summary`, `detail`, `ongoing`) 모두 존재
- `category` 값이 4개 옵션 중 하나
- `future_plan_details`가 `future_plan` 클러스터에만 존재

**실패 처리:**
- 검증 실패 → 해당 클러스터 재분석 1회
- 2회 연속 실패 → `parse_failed: true` 기록 후 스킵

---

#### Step 5: LLM 종합 분석

**처리 주체:** 에이전트 직접 수행 (LLM)

**입력:** `analysis_{날짜}_{기업명}.json` 전체 (파일 재로드)

**분석 구조:**

```
1. 수집 개요
   - 총 수집 기사 수, 유효 클러스터 수, 분석 기간
   - 국내/해외 기사 비율, 언론사 다양성
   - 해외 커버리지 부재 여부 명시

2. 긍정 사건 분석
   - 사건 목록 (날짜 / 제목 / 영향 규모 테이블)
   - 반복 등장 긍정 테마 (빈도 포함)
   - 가장 임팩트 큰 긍정 사건 TOP 3 및 근거

3. 부정 사건 분석
   - 사건 목록 (날짜 / 제목 / 영향 규모 / **지속 여부** 테이블)
     ▸ ongoing=true 사건: 행 배경을 강조색(리포트 생성 시 적색 계열) 적용
   - 반복 등장 부정 테마 (빈도 포함)
   - **현재 진행 중인 리스크 집중 기술** (ongoing=true 사건 전체, 투자자 최우선 확인 항목)
   - 가장 임팩트 큰 부정 사건 TOP 3 및 근거

4. 사건 타임라인
   - 분석 기간 전체를 시계열로 나열 (날짜 / 사건 / 긍정·부정 / 지속 여부 구분)
   - 6개월 단위 구간별 긍정·부정 사건 건수 요약
   - 특이 구간 (사건 집중 시기) 식별
   - 진행 중인 사건의 단계 변화(예: 협상→계약→납품)를 서술로 기술

5. 미래 추진 계획 통합
   - 계획 목록 전체 (목표 / 시기 / 투자금액 테이블)
   - 단기(1년 이내) / 중기(1~3년) / 장기(3년 초과) 분류
   - ※ 이행 가능성의 재무 체력 평가는 종합 리포트 에이전트에서 수행.
     여기서는 "뉴스에서 언급된 재무 관련 발언" 수준만 인용.
   - 아직 공식 발표 없는 영역 (시장이 기대하지만 미발표)

6. 이슈 패턴 및 리스크 평가
   - 구조적 리스크 (일회성이 아닌 반복·지속 이슈)
   - 핵심 모멘텀 테마 (지속 등장하는 긍정 동인)
   - 국내외 뉴스 온도 차이 (시각 차이가 있는 경우)

7. 종합 평가
   - 최근 1년 사건 기반 기업 현황 평가 (한 단락)
   - 주목해야 할 향후 일정 (미래 계획 중 구체적 시기 명시된 항목)
   - 종합 리포트 에이전트를 위한 핵심 인사이트 3~5개 불릿
```

**성공 기준 (LLM 자기 검증):**
- 7개 섹션 모두 존재
- 타임라인에 날짜 기반 정렬 확인
- 미래 추진 계획에 시기 분류(단기/중기/장기) 포함
- 모든 수치 인용 시 출처 기사 날짜 또는 클러스터 ID 명시
- 부정 사건 섹션에 ongoing 리스크 항목 존재

**실패 처리:**
- 자기 검증 실패 → 해당 섹션 재작성 최대 1회
- 유효 클러스터 < 5건 → 신뢰도 낮음 경고 삽입 후 진행

#### Step 6: 문서 생성

**처리 주체:** 스크립트 (`generate_md.py`, `generate_docx.py`)  
**라이브러리:** `python-docx` (Node.js/npm 의존성 없음, Python 단일 환경)

**마크다운 리포트 (.md):**
- Step 5 분석 전체 텍스트
- 사건 타임라인은 마크다운 테이블로 표현
- ongoing 리스크 행에 `> ⚠️` 표시 등으로 강조
- `output/report_{날짜}_{기업명}.md` 저장

**Word 리포트 (.docx) — 테이블 기반, 다이어그램 없음:**
- 표지 (기업명, 분석일자, 수집 기사 수, 분석 기간)
- 목차 자동 생성
- 긍정/부정 사건 목록: 컬러 테이블 (긍정: 파란 계열, 부정: 붉은 계열)
- **ongoing=true 사건**: 해당 행 배경을 더 진한 적색 계열로 강조
- 사건 타임라인: 날짜순 테이블 (ongoing 행 강조 포함)
- 미래 추진 계획 테이블: 시기 기준 오름차순 정렬 (단기/중기/장기 섹션 구분)
- `output/report_{날짜}_{기업명}.docx` 저장

**성공 기준:**
- 두 파일 모두 존재
- docx 유효성 검증 통과

**실패 처리:**
- docx 생성 실패 → md만 최종 산출, 오류 로그 기록

### 2.3 LLM 판단 영역 vs 코드 처리 영역 요약

| 단계 | 처리 주체 | 이유 |
|------|----------|------|
| 뉴스 검색 | Firecrawl MCP (에이전트 직접 호출) | 외부 API 호출 |
| 기사 본문 fetch | Firecrawl MCP (에이전트 직접 호출) | HTTP 요청 |
| 중복 제거·중요도 필터링 | 스크립트 (preprocess.py) | 규칙 기반 반복 처리 |
| 언어 감지 | 스크립트 (preprocess.py) | 결정론적 분류 |
| 이슈 클러스터링 | **LLM** (temperature=0) | 의미 기반 유사도 판단 |
| 사건 분류 (긍정/부정/미래계획/ongoing) | **LLM** | 맥락 기반 정성 판단 |
| 영향 규모·범위 평가 | **LLM** | 다차원 종합 추론 |
| 타임라인·패턴 도출 | **LLM** | 시계열 교차 분석 |
| 문서 생성 | 스크립트 (python-docx) | 파일 I/O |

### 3.2 CLAUDE.md 핵심 섹션 목록

| 섹션 | 내용 요약 |
|------|----------|
| 역할 정의 | 뉴스 수집·사건 분석 에이전트, 팩트 레이어 담당, 개인 투자자용 |
| 입력 파라미터 처리 | 기업명/영문명/종목코드 파싱, 기간 기본값 2년, --reuse 플래그 |
| 수집 도구 | Firecrawl MCP 직접 호출 (firecrawl_search + firecrawl_scrape), 사용량 초과 시 WebSearch + crawl4ai_scrape로 fallback |
| reuse 모드 | glob으로 *_{기업명}_news 탐색 → 최신 폴더 재활용 → 신규 기사만 추가 |
| 검색 쿼리 구성 규칙 | 국내 3종 필수 + 해외 3종 선택적 (영문명 제공 시) |
| 해외 뉴스 정책 | 스니펫 수준 수집 허용, 0건이어도 진행, 리포트에 명시 |
| LLM 호출 설정 | temperature=0 (클러스터링·분석 모든 단계) |
| 분류 판단 기준 | 긍정/부정/미래계획 분류 판단 원칙, ongoing 판단 기준, 추측 기사 배제 |
| 출력 경로 규칙 | `./{날짜}_{기업명}_news/` 폴더 명명 규칙 |
| 리스크 강조 규칙 | ongoing=true 부정 사건은 색상 강조, 투자자 최우선 확인 항목 |
| 금지 사항 | 추측성 내용 사실로 기술 금지, 미발표 계획 포함 금지, 수치 임의 계산 금지 |
