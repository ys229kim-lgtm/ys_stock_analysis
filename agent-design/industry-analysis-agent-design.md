# 산업 분석 Agent 설계서

> **문서 목적**: Claude Code에서 구현 시 참조할 계획서  
> **작성 기준**: Telegram MCP(산업 리포트 수집) + 웹 검색 + yfinance MCP(해외) + korea-stock-mcp(국내) 병합 분석  
> **분석 범위**: 산업 개요·밸류체인·경쟁 구도·수급 사이클·글로벌 트렌드·규제·시장 규모 + 단기(1년)·중기(1~3년) 방향성  
> **확률적 전망**: 시나리오별 실현 가능성(%) 명시 (데이터 부족 시 LLM 추론 허용, 레이블 의무화)  
> **출력 폴더**: 독립 프로젝트 폴더 (`{날짜}_{기업명}_industry/`)  
> **목표 실행 시간**: 1~2시간 심층 분석  
> **최우선 경계 사항**: 산업 분류 오류 → 이후 모든 단계 오염 (도미노 효과)

---

## 1. 작업 컨텍스트 문서

### 1.1 배경 및 목적

주식 분석 멀티에이전트 시스템의 **네 번째 서브에이전트**로, 대상 기업이 속한 산업의 구조·현황·전망을 분석한다. 기업 단위 분석(DART·Telegram·News agent)과 달리 **산업 레벨의 매크로 시각**을 담당하며, 해당 기업이 순풍을 타는 산업에 있는지 역풍을 맞는 산업에 있는지를 판단하는 근거를 제공한다.

**이 에이전트가 답하는 핵심 질문:**
- 이 기업이 속한 산업은 구조적으로 성장하는가, 수축하는가?
- 향후 1년간, 그리고 1~3년간 이 산업에 가장 큰 영향을 미칠 요인은 무엇인가?
- 긍정·부정 시나리오별 실현 가능성은 어느 정도인가?

### 1.2 산업 분류 결정 프로세스

에이전트 시작 시 **가장 먼저** 대상 산업을 확정한다. **산업 분류 오류는 이후 모든 단계(키워드·수집·분석)를 오염시키는 도미노 효과를 유발하므로, 불확실할 경우 반드시 사용자 확인을 거친다.**

```
기업명 입력
    │
    ▼
[1차] yfinance MCP로 sector/industry 조회
    │
    ├─ 명확한 값 반환 → [2단계 제안] 진행
    │
    └─ "Unknown" 또는 반환 실패
            → [2차] DART search_business_information으로
                    '사업의 개요' 텍스트 가져와 LLM이 산업명 추론
    │
    ▼
[2단계 산업 제안] LLM이 두 레벨로 제안
    예시: "반도체(넓은 산업)"와 "HBM 메모리(핵심 세그먼트)"
    → 사용자가 분석 레벨 선택 (둘 중 하나, 또는 두 레벨 모두)
    │
    ▼
복합 사업 기업인가?
    ├─ YES (지주사, 복합 사업, 매출 비중 분산 등)
    │       → 후보 산업 2~4개 도출 후 사용자에게 선택 요청
    │         예시:
    │         "이 기업은 다음 산업군에 걸쳐 있습니다.
    │          1) 반도체 — 매출 비중 약 60%, 대표 제품: DRAM/HBM
    │          2) 디스플레이 — 매출 비중 약 25%, 대표 제품: OLED 패널
    │          3) 가전 — 매출 비중 약 15%, 대표 제품: TV/냉장고
    │          어떤 산업을 분석할까요? 복수 선택 가능(최대 3개)."
    │         → 사용자 선택 후 Step 0 진행
    │
    └─ NO  → 산업명 확정 + 사용자에게 최종 확인 후 Step 0 진행
              "'{산업명}' 산업으로 분석을 시작합니다. 맞습니까?"
```

> **복수 산업 선택 시**: 산업별로 독립 JSON(`analysis_{날짜}_{기업명}_{산업명}.json`) 생성, 최종 docx는 하나로 통합(산업 A → 산업 B 순서로 이어서 기술)  
> **2단계 레벨 선택 시**: 선택된 레벨로 키워드·검색·분석 범위를 모두 재조정

### 1.3 입출력 정의

| 구분 | 항목 | 설명 |
|------|------|------|
| **입력** | 기업명 (필수) | 산업 분류 기준점 |
| **입력** | 영문 기업명 (선택) | 해외 자료 검색용 |
| **입력** | 산업명 (선택) | 사전 지정 시 분류 단계 스킵 |
| **입력** | 분석 기간 (선택) | 기본값: 단기(1년) + 중기(1~3년) 전망 |
| **출력** | 출력 폴더 | `./{날짜}_{기업명}_industry/` (없으면 자동 생성) |
| **출력** | 텔레그램 수집 원본 | `./{날짜}_{기업명}_industry/raw_reports/` |
| **출력** | 수집 메타데이터 JSON | `./{날짜}_{기업명}_industry/collection_meta_{날짜}_{기업명}.json` |
| **출력** | 산업 데이터 JSON | `./{날짜}_{기업명}_industry/industry_data_{날짜}_{기업명}.json` |
| **출력** | 분석 구조화 JSON | `./{날짜}_{기업명}_industry/analysis_{날짜}_{기업명}.json` |
| **출력** | 분석 마크다운 리포트 | `./{날짜}_{기업명}_industry/report_{날짜}_{기업명}.md` |
| **출력** | 분석 Word 리포트 | `./{날짜}_{기업명}_industry/report_{날짜}_{기업명}.docx` |

### 1.4 분석 7대 영역

| 영역 | 핵심 내용 |
|------|----------|
| 산업 개요 및 밸류체인 | 산업 정의, 세그먼트 구조, 밸류체인 단계별 주요 플레이어 |
| 시장 규모 및 성장률 전망 | 현재 시장 규모, TAM, CAGR, 단기(1년)·중기(3년) 전망 수치 |
| 주요 플레이어 경쟁 구도 | 국내외 주요 기업, 점유율, 경쟁 강도, 대상 기업의 포지션 |
| 수요·공급 사이클 분석 | 현재 사이클 위치(LLM 판단), 정량 기준 지표: 제품 가격 QoQ 추이·산업 재고/출하 비율, 단기·중기 반전 가능성 |
| 글로벌 트렌드 및 기술 변화 | 산업 패러다임 변화, 신기술 도입, 게임체인저 요인 |
| 규제 환경 | 국내외 주요 규제, 정책 지원, 리스크 규제 변화 |
| 확률적 방향성 전망 | 단기(1년)·중기(1~3년) 각각 긍정·기본·부정 시나리오 + 실현 확률(%) |

### 1.5 주요 제약조건

- 텔레그램 산업 리포트는 키워드 검색 기반 → 관련 없는 리포트 혼입 가능, LLM이 관련성 판단
- 텔레그램 리포트 수집 결과가 저조할 경우, 해당 산업 관련 채널 구독을 사용자에게 제안
- 텔레그램 검색 키워드는 LLM이 런타임에 산업명·세그먼트 기반으로 자동 생성
- yfinance MCP: **해외 기업** 시장 데이터(주가·섹터·PER) 전용; 산업 리포트 대체 불가
- korea-stock-mcp: **국내 기업** 시장 데이터(시가총액·52주 범위·PER·PBR) 수집 전용
- 확률 수치: 텔레그램/웹 데이터 근거 기반 우선, 데이터 부족 시 LLM 추론 허용하되 **반드시 '데이터 부족 추정값' 레이블 표기** 의무화
- 복수 산업 선택 시 분석 시간이 선형으로 증가 → 최대 3개 산업으로 제한
- 페이월 차단 웹 기사 → 스니펫만 활용, 메타데이터에 `paywall: true` 표기
- 산업 분류 오류는 이후 전체 파이프라인 오염 → Step 0에서 사용자 최종 확인 필수

### 1.6 용어 정의

| 용어 | 정의 |
|------|------|
| TAM | Total Addressable Market, 전체 목표 시장 규모 |
| 수급 사이클 | 특정 산업의 수요·공급 균형이 주기적으로 변동하는 패턴 |
| 밸류체인 | 원재료 → 부품 → 제조 → 유통 → 최종 소비까지의 가치 창출 단계 |
| 확률적 시나리오 | 분석 데이터 근거로 각 방향성의 실현 가능성을 % 형태로 제시 |
| yfinance MCP | Yahoo Finance 데이터를 Claude Code에서 호출하는 MCP 서버 |

## 2. 워크플로우 정의

### 2.1 전체 흐름

```
[입력: 기업명]
        │
        ▼
[Step 0] 산업 분류 확정 + 출력 폴더 생성
   yfinance MCP로 sector 1차 조회
   → Unknown/실패 시 DART 사업보고서 LLM 인퍼로 보완
   → LLM이 넓은 산업 + 핵심 세그먼트 2단계 제안
   → 사용자 최종 확인 (분류 오류 방지)
   → 폴더 생성
        │
        ▼
[Step 1 + Step 3 병렬 시작] ──────────────────────────
        │                                              │
        ▼                                              ▼
[Step 1] 텔레그램 산업 리포트 수집         [Step 3] 웹 검색 기반 산업 데이터 수집
   LLM이 산업명 기반 키워드 자동 생성         웹 검색: 7대 영역별 쿼리로 국내+해외
   telegram-mcp: 검색 + 파일 다운로드         yfinance MCP: 해외 기업 시장 데이터
   → raw_reports/ 저장                         korea-stock-mcp: 국내 기업 시장 데이터
        │                                      → industry_data_{날짜}_{기업명}.json
        ▼                                              │
[Step 2] 텔레그램 리포트 텍스트 추출        ◄──────────┘
   스크립트: PDF/이미지 텍스트 추출
   중복 제거, 관련성 필터링
   저조 시 추천 채널 구독 제안
        │
        ▼ (Step 2 완료 + Step 3 완료 후 진행)
[Step 4] LLM 통합 분석
   에이전트 직접 수행: 텔레그램 리포트 + 웹 데이터 교차 분석
   → 7대 영역 구조화 분석 + 확률적 시나리오 도출
   → JSON 구조 체크리스트 자동 검증 (확률 합계 = 100% 포함)
   → analysis_{날짜}_{기업명}_{산업명}.json 저장 (복수 산업 시 산업별)
        │
        ▼
[Step 5] 문서 생성
   스크립트(python-docx): 통합 docx + 산업별 md 생성
        │
        ▼
[출력: ./{날짜}_{기업명}_industry/ 내 전체 산출물]
```

### 2.2 단계별 상세 정의

---

#### Step 0: 산업 분류 확정 + 출력 폴더 생성

**처리 주체:** yfinance MCP + DART MCP + LLM + 스크립트 (`setup_dirs.py`)

**산업 분류 수행 순서:**

1. **yfinance MCP 1차 조회**: 티커 기반 `sector` / `industry` 필드 반환
2. **보완 조회 (1차 실패 시)**: DART `search_business_information`으로 '사업의 개요' 텍스트 추출 → LLM이 산업명 인퍼
3. **2단계 산업 레벨 제안**: LLM이 넓은 산업(예: 반도체)과 핵심 세그먼트(예: HBM 메모리) 두 레벨을 제시, 사용자가 분석 레벨 선택
4. **복합 사업 판단**: 매출 비중이 분산된 기업은 후보 산업 2~4개 도출 후 사용자 선택
5. **최종 사용자 확인**: 단일 산업이라도 분석 시작 전 반드시 확인 요청 (분류 오류 방지)

**후보 제시 형식 (사용자 선택 요청 시):**
```
[산업 분류 확인 필요]
이 기업은 여러 산업에 걸쳐 있습니다. 분석할 산업을 선택해 주세요.

1) {산업명A} — 매출 비중 약 {N}%, 대표 제품/서비스: {예시}
2) {산업명B} — 매출 비중 약 {N}%, 대표 제품/서비스: {예시}
3) {산업명C} — 매출 비중 약 {N}%, 대표 제품/서비스: {예시}

복수 선택 가능 (최대 3개). 번호로 답해주세요.
```

**2단계 레벨 제시 형식:**
```
[분석 레벨 선택]
'{기업명}'의 산업 분류는 다음과 같습니다:

▸ 넓은 산업: {산업명} (예: 반도체)
  → 밸류체인 전체, 글로벌 경쟁사 포함, 시장 규모 크게 잡힘

▸ 핵심 세그먼트: {세그먼트명} (예: HBM 메모리)
  → 대상 기업 매출 핵심 영역, 세밀한 수급 분석 가능, 시장 규모 작게 잡힘

어떤 레벨로 분석할까요? (둘 다 선택 가능)
```

**출력 폴더 생성:**
```
./{날짜}_{기업명}_industry/
  ├── /raw_reports/       # 텔레그램 수집 원본
  ├── /extracted_text/    # 추출 텍스트
  └── /output/            # 분석 결과 산출물
```

**성공 기준:** 산업명 사용자 확인 완료 + 3개 폴더 생성 완료  
**실패 처리:** yfinance·DART 모두 조회 실패 시 → 기업명 기반 LLM 추론으로 후보 3개 제시 후 사용자 선택  
**⚠️ 산업 분류 오류 방지**: 사용자 명시적 확인 없이 Step 1 진행 불가

---

#### Step 1: 텔레그램 산업 리포트 수집 (Step 3과 병렬 시작)

**처리 주체:** telegram-mcp (도구 호출) + 스크립트 (`collect_reports.py`)

**검색 키워드 구성:**

LLM이 산업명과 선택된 세그먼트를 기반으로 런타임에 키워드를 자동 생성한다.

| 키워드 유형 | 예시 (반도체/HBM) |
|-----------|-----------------|
| 산업명 단독 | `반도체`, `semiconductor` |
| 산업명 + 리포트 | `반도체 산업분석`, `반도체 리포트` |
| 산업명 + 전망 | `반도체 전망 2025`, `반도체 outlook` |
| 세그먼트 키워드 (LLM 자동 생성) | `HBM`, `DRAM`, `파운드리` → LLM이 산업별 추가 도출 |

**수집 범위:** 최근 1년, 접속 계정 구독 채널 전체  
**다운로드 대상:** 첨부 파일(PDF·이미지·텍스트) + 텍스트 메시지  
**저장:** `raw_reports/{날짜}_{채널명}_{파일명}`

**분기조건:**
```
수집 결과 저조(5건 미만)?
  └─ 에이전트가 관련 텔레그램 채널 구독 제안:
     "이 산업 관련 리포트가 충분하지 않습니다.
      다음 채널 구독을 권장합니다: [LLM이 추천 채널 목록 제시]"

수집 결과 = 0건?
  ├─ YES → 스킵 + 로그 기록 ("텔레그램 산업 리포트 없음"), Step 3 결과만으로 진행
  └─ NO  → Step 2 진행

파일 다운로드 실패 (단건)?
  ├─ 재시도 2회
  └─ 실패 시 → 메타데이터만 기록, 스킵
```

**성공 기준:** 수집 0건이어도 실패 아님 (웹 검색으로 대체 가능)  
**실패 처리:** telegram-mcp 연결 오류 → 재시도 3회 → 스킵 후 Step 3 결과로만 진행, 리포트에 텔레그램 데이터 부재 명시

---

#### Step 2: 텔레그램 리포트 텍스트 추출 및 정제

**처리 주체:** 스크립트 (`extract_and_filter.py`)

**수행 작업:**
- PDF 텍스트 추출 (`pdfplumber`), 실패 시 OCR (`pytesseract`)
- 이미지 OCR 처리
- 파일 해시 기반 중복 제거
- **관련성 필터링**: 파일명 + 추출 텍스트 첫 500자에 산업명 키워드 포함 여부 확인
  - 포함 → 유효 리포트로 분류
  - 미포함 → `irrelevant: true` 태깅, 분석에서 제외
- `collection_meta_{날짜}_{기업명}.json` 생성

**성공 기준:** 관련성 필터링 후 1건 이상 유효 리포트 존재 (0건도 허용, 웹 데이터로 대체)

---

#### Step 3: 웹 검색 기반 산업 데이터 수집 (Step 1과 병렬 시작)

**처리 주체:** 웹 검색 도구 + yfinance MCP(해외) + korea-stock-mcp(국내) + 스크립트 (`collect_web_data.py`)

**7대 영역별 웹 검색 쿼리:**

| 영역 | 국내 쿼리 예시 | 해외 쿼리 예시 |
|------|--------------|--------------|
| 산업 개요·밸류체인 | `{산업명} 산업 구조 밸류체인` | `{industry} value chain structure` |
| 시장 규모·성장률 | `{산업명} 시장 규모 전망 2025` | `{industry} market size forecast 2025` |
| 경쟁 구도 | `{산업명} 주요 기업 점유율 순위` | `{industry} market share major players` |
| 수요·공급 사이클 | `{산업명} 수급 재고 현황 2025` | `{industry} supply demand cycle inventory` |
| 글로벌 트렌드·기술 | `{산업명} 기술 트렌드 혁신` | `{industry} technology trend innovation` |
| 규제 환경 | `{산업명} 규제 정책 정부 지원` | `{industry} regulation policy subsidy` |
| 단기·중기 전망 | `{산업명} 전망 2025 2026 2027` | `{industry} outlook 2025 2026 midterm forecast` |

**시장 데이터 수집 (국내/해외 분리):**

| 구분 | 도구 | 수집 항목 |
|------|------|----------|
| **국내 주요 기업** | korea-stock-mcp | 시가총액, 52주 주가 범위, PER, PBR (상위 5개) |
| **해외 주요 기업** | yfinance MCP | 시가총액, 52주 주가 범위, PER, PBR (상위 5개) |
| **산업 ETF** | yfinance MCP | ETF 가격 추이 (예: SOXX, SMH, 해당 시) |
| **섹터 수익률** | yfinance MCP | S&P 500 대비 섹터 수익률 비교 |

> 국내 기업만 존재하는 산업(예: KOSPI 중소형 섹터)은 korea-stock-mcp만 활용

**저장:** `industry_data_{날짜}_{기업명}.json`

**성공 기준:**
- 7대 영역 중 5개 이상 데이터 확보
- 국내 또는 해외 주요 기업 시장 데이터 최소 5개 기업 수집

**실패 처리:**
- 특정 영역 데이터 부족 → 리포트 해당 섹션에 "데이터 불충분" 명시 후 진행
- korea-stock-mcp / yfinance MCP 오류 → 스킵 + 웹 검색으로 대체

#### Step 4: LLM 통합 분석

**처리 주체:** 에이전트 직접 수행 (LLM 판단 영역)

**입력 소스 우선순위:**
1. 텔레그램 수집 산업 리포트 (전문 애널리스트 시각 — 최우선)
2. 웹 검색 데이터 (최신 정보 보완)
3. yfinance 시장 데이터 (정량 근거)

**7대 영역 분석 상세:**

```
1. 산업 개요 및 밸류체인
   - 산업 정의 및 범위 (어디서 어디까지)
   - 밸류체인 단계별 구조 (원재료 → 최종 소비)
   - 각 단계별 주요 플레이어 및 대상 기업의 위치
   - 산업 내 핵심 경쟁 요소 (가격/기술/속도 등)

2. 시장 규모 및 성장률 전망
   - 현재 글로벌 시장 규모 (출처 명시)
   - 국내 시장 규모 (가능 시)
   - 단기(1년): 예상 시장 규모 및 성장률
   - 중기(3년): 예상 시장 규모 및 CAGR 범위
   - 성장 동인 Top 3

3. 주요 플레이어 경쟁 구도
   - 글로벌 Top 5 기업 및 점유율
   - 국내 주요 플레이어
   - 대상 기업의 포지션 및 경쟁 우위/열위
   - 경쟁 강도 평가 (Porter 5 Forces 간략 적용)

4. 수요·공급 사이클 분석
   - 현재 사이클 위치 (호황 / 하락 / 바닥 / 회복 중) — LLM이 아래 정량 지표를 종합 판단
     ① 제품 가격 추이 (전분기 대비 QoQ %, 최근 2~3분기)
     ② 산업 재고/출하 비율 (웹 검색 + 텔레그램 리포트 기반)
     ③ 텔레그램 리포트에서 '바닥', '회복', '상승 전환' 등 언어적 시그널
   - 재고 수준 및 추이
   - 단기(1년) 내 사이클 반전 가능성 및 시점 예측
   - 중기(1~3년) 사이클 방향성 및 구조적 변화 여부

5. 글로벌 트렌드 및 기술 변화
   - 산업 패러다임 변화 요인 (AI, ESG, 탈탄소 등)
   - 게임체인저 기술 및 도입 속도
   - 지정학적 요인 (공급망 재편, 미중 갈등 등)

6. 규제 환경
   - 국내 규제·정책 지원 현황
   - 해외 주요 규제 (특히 미국·EU·중국)
   - 단기(1년) 내 예상 규제 변화 및 영향
   - 중기(1~3년) 규제 방향성 (강화 / 완화 / 불확실)

7. 확률적 방향성 전망

   [단기 전망 — 1년 이내]
   ┌─────────────────────────────────────────────────────┐
   │ 시나리오      │ 핵심 조건              │ 확률        │
   │ Positive      │ 긍정 요인 실현 시      │  X%         │
   │ Base Case     │ 현재 추세 유지 시      │  Y%         │
   │ Negative      │ 리스크 현실화 시       │  Z%         │
   │               │ (X + Y + Z = 100%)     │             │
   └─────────────────────────────────────────────────────┘

   [중기 전망 — 1~3년]
   ┌─────────────────────────────────────────────────────┐
   │ 시나리오      │ 핵심 조건              │ 확률        │
   │ Positive      │ 구조적 성장 실현 시    │  X%         │
   │ Base Case     │ 완만한 성장 지속 시    │  Y%         │
   │ Negative      │ 구조적 리스크 현실화   │  Z%         │
   │               │ (X + Y + Z = 100%)     │             │
   └─────────────────────────────────────────────────────┘

   각 시나리오별 공통 기술 항목:
   - 전제 조건 (2~3개 핵심 조건)
   - 예상 시장 성장률 또는 핵심 지표 범위
   - 확률 근거: 텔레그램 리포트 컨센서스 + 웹 데이터 기반 명시
   - 대상 기업에 미치는 시나리오별 영향 (한 줄 요약)

   단기·중기 전망 간 방향성 일치 여부 및 변곡점 시기 명시
```

**확률 산출 원칙:**
- 텔레그램 리포트 다수가 긍정 시각 → Positive 확률 상향 반영
- 데이터 충분 시: 반드시 "~을 근거로 X% 추정" 형식
- 데이터 부족 시(리포트 2건 이하 또는 상충): LLM 산업 상식·거시 컨텍스트 기반 추론 허용, **반드시 '데이터 부족 추정값' 레이블 표기** (예: `"probability": "35% (데이터 부족 추정값)"`)
- 리포트가 강세·약세로 충돌 시: 두 시각을 각각 요약 후 확률 범위로 표기 (예: 30~45%)
- 3개 시나리오 합산 = 100% 유지
- 확률 범위가 불확실한 경우 → 범위로 표기 (예: 30~40%)

**성공 기준 (구조 체크리스트 자동 검증):**

분석 완료 후 스크립트가 JSON을 파싱하여 아래 항목을 코드로 자동 확인한다:
- [ ] JSON 7대 영역 키(`overview`, `market_size`, `competition`, `supply_demand`, `global_trends`, `regulation`, `scenarios`) 모두 존재
- [ ] `scenarios.short_term` 및 `scenarios.mid_term`에 `positive`, `base`, `negative` 모두 존재
- [ ] 단기 3개 확률 합계 = 100% (범위 표기 시 중간값으로 계산)
- [ ] 중기 3개 확률 합계 = 100%
- [ ] `target_company_position` 필드 값 존재
- [ ] 각 수치에 `source` 또는 `label` 필드 존재

검증 실패 항목 발견 시 → 해당 섹션만 재작성 최대 1회. 재작성 후에도 실패 시 사용자에게 에스컬레이션.

**실패 처리:**
- 텔레그램 리포트 0건 + 웹 데이터도 부족 → 에스컬레이션 (산업명 재확인 또는 검색 키워드 수정 요청)

**성공 기준:** md 파일(단일 또는 복수) + docx 파일 모두 존재, python-docx 유효성 검증 통과  
**실패 처리:** docx 생성 실패 → md만 최종 산출, 오류 로그 기록

### 3.3 에이전트 구조

**단일 에이전트** 구조 채택

**근거:** 산업 분류 → 데이터 수집 → 분석의 흐름이 순차적이고, 텔레그램 리포트와 웹 데이터를 교차 분석하는 종합 단계에서 이전 수집 컨텍스트가 필요. 산업이 복수로 선택된 경우에도 동일 에이전트가 산업별로 순환하여 처리.

**오케스트레이터 통합:**

이 에이전트는 기업 종합 분석 오케스트레이터(`C:/claude/stock/CLAUDE.md`)에서 **4번째 에이전트로 항상 병렬 실행**된다.

```
[오케스트레이터] "기업 분석해줘" 수신
        │
        ├─ Agent 1: financial-analysis-agent  (병렬)
        ├─ Agent 2: telegram-report-agent     (병렬)
        ├─ Agent 3: news-analysis-agent       (병렬)
        └─ Agent 4: industry-analysis-agent   (병렬) ← 이 에이전트
```

충돌 조율: 각 에이전트는 독립 산출물만 생성. 산업 분석 결과(긍정)와 재무 분석 결과(적자 지속) 등 충돌 신호의 해석과 최종 판단은 종합 리포트 에이전트가 담당.

### 3.4 스킬 파일 목록 및 역할

## 4. 설계 결정 근거 (주요 판단 기록)

| 결정 항목 | 선택 | 근거 |
|----------|------|------|
| 단일 vs 멀티 에이전트 | 단일 에이전트 | 수집→분석 컨텍스트 연속성, 복수 산업은 순환 처리 |
| 산업 분류 순서 | yfinance 1차 → DART 사업보고서 LLM 인퍼 | yfinance가 Unknown 반환 시 DART 보완; 최종 확인은 사용자 |
| 2단계 산업 레벨 제안 | 넓은 산업 + 핵심 세그먼트 LLM 제안 | 세분화 수준에 따라 수집 키워드·경쟁사·시장 규모 전체가 달라짐 |
| 산업 분류 오류 방지 | Step 0에서 반드시 사용자 최종 확인 | 최우선 우려: 분류 오류가 이후 모든 단계를 오염시키는 도미노 효과 |
| 텔레그램 0건 허용 | 스킵 후 계속 진행 + 채널 구독 제안 | 웹 검색으로 대체 가능, 저조 시 사용자에게 추천 채널 제시 |
| 텔레그램 키워드 | LLM 런타임 자동 생성 | 산업별 세그먼트가 다양해 사전 정의 목록 유지가 어렵고, LLM이 유연하게 도출 |
| 확률 3개 시나리오 | Positive + Base + Negative | 양극단만 있으면 현실 왜곡, 기본 시나리오가 핵심 |
| 확률 데이터 부족 시 | LLM 추론 허용 + '데이터 부족 추정값' 레이블 의무 | 데이터가 없어도 숫자 요구가 발생하므로 투명한 레이블로 신뢰도 명시 |
| 확률 자기검증 | JSON 파싱 구조 체크리스트 자동화 | 코드로 검증 가능한 항목(키 존재, 합계=100%)은 자동화하여 재작성 최소화 |
| 수급 사이클 판단 | LLM 자유 판단 + 제품 가격 QoQ·재고/출하 비율 정량 참조 | 완전 자유보다 정량 앵커 제공으로 판단 일관성 향상 |
| 국내/해외 시장 데이터 | korea-stock-mcp(국내) / yfinance(해외) 분리 | yfinance는 한국 주식 커버리지 불완전, korea-stock-mcp가 이미 시스템에 연동됨 |
| Step 1+3 병렬 시작 | 텔레그램 수집과 웹 검색 동시 시작 | 두 수집이 독립적이며 Step 4가 둘 다 완료를 기다리므로 병렬로 시간 단축 가능 |
| docx 라이브러리 | python-docx (Node.js 제거) | 나머지 스크립트가 모두 Python 환경; 런타임 통일로 유지보수 단순화 |
| 복수 산업 출력 구조 | 통합 docx + 산업별 별도 JSON | 리포트는 하나로 읽기 편하게, 데이터는 종합 리포트 에이전트가 산업별로 참조 가능하게 |
| 분석 유효기간 | 없음 (매 실행 시 신규) | 날짜 폴더로 버전 관리, 재분석 필요성은 사용자가 직접 판단 |
| 목표 실행 시간 | 1~2시간 심층 분석 | 매매 판단 전 사전 조사 용도, 품질이 속도보다 중요 |
| 오케스트레이터 통합 | 항상 4번째 병렬 에이전트로 실행 | 기업 분석 = 재무 + 리포트 + 뉴스 + 산업 4축 병렬 분석이 완성된 시스템 |
| 에이전트 간 충돌 조율 | 종합 리포트 에이전트가 담당 | 각 서브에이전트는 독립 산출물만 생성, 충돌 해석은 상위 레이어 역할 |
| 데이터 소스 우선순위 | 텔레그램 > 웹 > korea-stock-mcp/yfinance | 전문 애널리스트 시각 > 일반 기사 > 시장 데이터 |
| 복수 산업 최대 3개 제한 | 하드 리밋 | 분석 시간·품질 유지, 핵심 산업 집중 유도 |
