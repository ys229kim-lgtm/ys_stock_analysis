# 기업 재무실적 분석 Agent 설계서

> **문서 목적**: Claude Code에서 구현 시 참조할 계획서  
> **작성 기준**: 단일 종목 분석 / DART MCP 데이터 / Python 시각화 / 경쟁사 비교 포함  
> **산출물 포맷**: 마크다운(.md) + Word 문서(.docx) + 재무 데이터(.docx 별도) 각 1개  
> **출력 폴더 형식**: `./{날짜}_{기업명}/` (실행 시점에 자동 생성)

---

## 1. 작업 컨텍스트 문서

### 1.1 배경 및 목적

주식 분석 멀티에이전트 시스템의 **첫 번째 서브에이전트**로, 기업의 정량적 재무 데이터를 수집·분석하고 시각화 결과물을 산출한다. 이 결과물은 이후 종합 리포트 생성 에이전트의 입력으로 사용된다.

**이 에이전트가 답하는 핵심 질문:**
- 이 기업의 재무 체력은 최근 10년간 개선되었는가, 악화되었는가?
- 동종업계 경쟁사 대비 어느 영역이 강점이고 어느 영역이 취약한가?
- 투자자 관점에서 주목해야 할 위험 신호(Red Flag)는 무엇인가?

### 1.2 입출력 정의

| 구분 | 항목 | 설명 |
|------|------|------|
| **입력** | 종목코드 (필수) | DART 표준 6자리 종목코드 (예: 005930) |
| **입력** | 경쟁사 종목코드 (선택) | 1~3개, 비교 분석용 |
| **입력** | 분석 기준연도 (선택) | 미입력 시 최근 연도 기준 자동 설정 |
| **출력** | 출력 폴더 | `./{날짜}_{기업명}/` — 없으면 자동 생성 (예: `./20260602_삼성전자/`) |
| **출력** | 정제된 재무 데이터 JSON | `./{날짜}_{기업명}/financials_{날짜}_{기업명}.json` |
| **출력** | 정제된 재무 데이터 Word | `./{날짜}_{기업명}/financials_{날짜}_{기업명}.docx` |
| **출력** | 차트 이미지 파일 묶음 | `./{날짜}_{기업명}/charts/` |
| **출력** | 재무분석 마크다운 리포트 | `./{날짜}_{기업명}/report_{날짜}_{기업명}.md` |
| **출력** | 재무분석 Word 리포트 | `./{날짜}_{기업명}/report_{날짜}_{기업명}.docx` |

### 1.3 분석 범위

**재무제표 기간:** 최근 10개 사업연도 (연결 기준 우선, 없으면 별도 기준)

**분석 5대 영역:**

| 영역 | 핵심 지표 |
|------|----------|
| 수익성 | 매출액, 영업이익, 순이익, 영업이익률, 순이익률, ROE, ROA |
| 안정성 | 부채비율, 유동비율, 이자보상배율, 순차입금비율 |
| 성장성 | 매출 YoY, 영업이익 YoY, CAGR(3년/5년/10년) |
| 현금흐름 | 영업CF, 투자CF, 재무CF, FCF, FCF 마진 |
| 수익구조 | 사업부문별 매출 비중 (DART 사업보고서 세그먼트 데이터) |

**경쟁사 비교:** 위 5개 영역의 핵심 지표를 최근 3~5년 기준으로 나란히 비교

### 1.4 주요 제약조건

- DART에 공시된 데이터만 사용 (비공개 데이터 활용 불가)
- 사업부문 세그먼트 정보는 기업에 따라 미공개 가능 → 스킵 후 로그 기록
- 금융업종 기업은 일반 재무비율 공식 적용 불가 → 업종 분류 확인 후 별도 처리
- 경쟁사 미입력 시 비교 섹션 전체 생략 (업종 평균 비교 미구현)

### 1.5 용어 정의

| 용어 | 정의 |
|------|------|
| DART | 금융감독원 전자공시시스템 (dart.fss.or.kr) |
| dart-mcp | DART API를 Claude Code에서 호출하는 MCP 서버 |
| FCF | Free Cash Flow = 영업CF - 자본적지출(CAPEX) |
| 이자보상배율 | 영업이익 ÷ 이자비용 (1 미만이면 위험 신호) |
| Red Flag | 투자 위험을 나타내는 정량적 임계값 초과 신호 |

## 2. 워크플로우 정의

### 2.1 전체 흐름

```
[입력: 종목코드 + 경쟁사코드]
        │
        ▼
[Step 1] DART 데이터 수집
   dart-mcp 호출 → 재무제표 10년치 + 사업부문 데이터
        │
        ▼ (수집 성공 여부 확인)
[Step 2] 데이터 정제 및 지표 계산
   스크립트: 결측치 처리, 파생 지표 계산, JSON 표준화
        │
        ▼
[Step 3] 시각화 생성
   스크립트: Python(matplotlib/plotly)으로 차트 이미지 생성
        │
        ▼
[Step 4] 경쟁사 데이터 수집 (경쟁사 입력된 경우)
   Step 1~2 반복 (경쟁사 각각)
        │
        ▼
[Step 5] LLM 분석 및 리포트 작성
   에이전트 직접 수행: 5개 영역 분석, 강약점, Red Flag 도출
        │
        ▼
[Step 6] 문서 생성
   마크다운 저장 + docx 변환
        │
        ▼
[출력: ./{날짜}_{기업명}/ 폴더 내 report.md + report.docx + financials.docx]
```

### 2.2 단계별 상세 정의

---

#### Step 1: DART 데이터 수집

**처리 주체:** dart-mcp (도구 호출)

**수집 항목:**
- 포괄손익계산서 (10개년)
- 재무상태표 (10개년)
- 현금흐름표 (10개년)
- 사업부문별 실적 (가능한 경우)
- 기업 기본정보 (업종코드, 상장여부 등)

**분기조건:**

```
연결재무제표 존재?
  ├─ YES → 연결 기준으로 수집
  └─ NO  → 별도 기준으로 수집 + 리포트에 주석 표기

금융업종 여부 (업종코드 확인)?
  ├─ YES → 분석 불가 안내 후 에스컬레이션
  └─ NO  → 정상 진행
```

**성공 기준:**
- 3개 재무제표(손익/재무상태/현금흐름) 모두 수집
- 최소 5개년 이상 데이터 존재

**실패 처리:**
- DART API 오류 → 자동 재시도 최대 3회 (30초 간격)
- 3회 후에도 실패 → 에스컬레이션 (사용자에게 종목코드 확인 요청)
- 현금흐름표만 없는 경우 → 스킵 + 로그 기록, 나머지 진행

---

#### Step 2: 데이터 정제 및 지표 계산

**처리 주체:** 스크립트 (`calculate_metrics.py`)

**수행 작업:**
- DART 원시 JSON → 표준화된 데이터프레임 변환
- **단위 자동 인식:** DART XBRL 메타데이터의 연단위(decimals/scaleFactors) 기반으로 원시값 단위 판별; 판별 실패 시 억원 기본값으로 처리 후 로그 기록
- **수치 표기 단위:** 조원 기준 (예: 매출 23.5조 원); 소수점 1자리 표시
- **분석 관닥 구간 명시:** XBRL 데이터 수집 가능한 최초 연도 ~ 최근 연도를 `financials.json`의 `data_range` 필드에 기록 (예: "2019–2024")
- 결측치 처리 (선형 보간 또는 N/A 표기)
- 파생 지표 계산 (영업이익률, ROE, FCF, 각종 비율)
- 연도별 YoY 성장률 계산
- CAGR 계산 (가용 연수에 따라 3년/5년/최대 10년 — 데이터가 짧으면 계산 가능한 구간만 산정)
- 결과를 `./{날짜}_{기업명}/financials_{날짜}_{기업명}.json`으로 저장

**성공 기준:**
- 스키마 검증: 필수 필드(매출, 영업이익, 순이익, 총자산, 총부채) 모두 존재
- 수치 타입 검증: 숫자형 확인
- 이상치 검증: 전년 대비 ±500% 이상 변동 시 플래그 표시

**실패 처리:**
- 스키마 검증 실패 → 자동 재시도 1회 (DART 재수집)
- 이상치 플래그 → 스킵 없이 데이터 유지, 리포트에 주석으로 기재

---

#### Step 3: 시각화 생성

**처리 주체:** 스크립트 (`generate_charts.py`)

**시각화 라이브러리:** matplotlib (정적 PNG 전용, plotly 미사용)

**차트 스타일 기준 (한국형):**
- 색상: 국내 금융정보 서비스(FnGuide/KIS 스타일) 준거 — 매출 파란계열(#1F3A93), 영업이익 진녹색(#1E8449), 순이익 주황(#CA6F1E)
- 테두리: 두꺼운 스파인 (linewidth=1.5), 격자선 옅은 회색
- 폰트: NanumGothic 우선 사용 — `matplotlib.rcParams['font.family'] = 'NanumGothic'` 코드를 스크립트 상단에 명시; 폰트 미설치 시 AppleGothic(macOS) / Malgun Gothic(Windows) 순 폴백
- 레이블: **영문/한글 병기** (예: "Revenue (매출액)", "Operating Profit (영업이익)")
- 수치 단위: 조원 표기 (1e12 나누기, 소수점 1자리)

- 12개 차트 파일 모두 생성 (세그먼트 데이터 없는 경우 `08` 제외 → 11개)

**실패 처리:**
- 개별 차트 생성 실패 → 스킵 + 로그 기록, 리포트에 "데이터 부족으로 미생성" 표기
- 경쟁사 데이터 없을 경우 → `09`~`12` 차트 생략

#### Step 4: 경쟁사 데이터 수집

**처리 주체:** Step 1~2 동일 스크립트, 경쟁사 종목코드로 반복 호출

**분기조건:**
- 경쟁사 코드 입력 없음 → Step 4 전체 스킵, Step 5로 진행
- 경쟁사 1~3개 → 각각 순차 처리

**성공 기준:** 경쟁사별로 Step 2와 동일 기준 적용

**실패 처리:** 특정 경쟁사 수집 실패 → 해당 경쟁사만 스킵 + 로그, 나머지 진행
**폴백 정책:** 모든 경쟁사 수집 실패 시 → 비교 섹션 전체 생략 후 메인 기업 단독 분석으로 최종 완료 (사용자 확인 없이 자동 진행)

---

#### Step 5: LLM 분석 및 리포트 작성

**처리 주체:** 에이전트 직접 수행 (LLM 판단 영역)

**분석 구조:**

```
1. 수익성 분석
   - 매출/이익 트렌드 해석 (성장 / 정체 / 역성장 / 반등)
   - 이익률 변화 원인 추론 (원가 구조, 사업 믹스 변화 등)
   - 경쟁사 대비 수익성 포지셔닝

2. 안정성 분석
   - 부채 수준의 절대적/상대적 평가
   - 이자보상배율 위험 구간 진입 여부
   - 유동성 위기 가능성 평가

3. 성장성 분석
   - 성장 모멘텀 변화 (가속 / 둔화 / 역전)
   - CAGR 관점에서의 장기 성장 체력 평가
   - 경쟁사 대비 성장 속도 비교

4. 현금흐름 분석
   - 영업 현금창출 능력 평가
   - CAPEX 투자 패턴 분석 (공격적 투자 vs 방어적 유지)
   - FCF 추이로 본 재무 여력

5. 수익구조 분석 (세그먼트 데이터 있는 경우)
   - 주력 사업부문 의존도
   - 사업 다각화 수준
   - 특정 사업부 리스크 집중 여부

6. 종합 평가
   - 강점 (Strengths): 지속적 우위 영역
   - 약점 (Weaknesses): 구조적 취약 영역
   - Red Flag 목록: 아래 임계값 기준으로 자동 도출
   - 핵심 모니터링 지표 제안
```

**리포트 작성 문체:**
- 스타일: **애널리스트 보고서 형식** — 연어(硬語) + 객관적 서술
- 예시: "2024년 매출액은 XX조 원으로 전년 대비 Z% 증가하였으며, 이는 [근거] 에 기인한다."
- 금지: 문어체 과장 표현, 추측성 전망 단언
- 언어: **한국어 본문 + 핵심 지표명 영문 병기** (예: "영업이익률(Operating Margin) 15.3%")

**Red Flag 임계값 기준 (에이전트 판단 기준점):**

> **적용 방식:** 아래 임계값은 **참조 기준점**으로만 사용. 업종 특성(예: 반도체의 부채비율 200%, 금융의 이자수익 구조 등)을 LLM이 스스로 감안하여 Red Flag 여부를 최종 판단한다. 임계값 초과 = 자동 Red Flag 아님.

| 지표 | 위험 임계값 | 심각 임계값 |
|------|-----------|-----------|
| 영업이익률 | 업종 맥락상 비정상 수준 | 3년 연속 하락 |
| 이자보상배율 | 2.0 미만 | 1.0 미만 |
| 부채비율 | 200% 초과 (업종 조정 필요) | 300% 초과 |
| FCF | 2년 연속 음수 | 3년 연속 음수 |
| 매출 성장률 | 2년 연속 역성장 | 3년 연속 역성장 |

**성공 기준 (LLM 자기 검증):**
- 5개 분석 영역 모두 서술 존재
- Red Flag 섹션 존재 (해당 없으면 "없음"으로 명기)
- 분석 근거로 실제 수치 인용
- 경쟁사 비교 시 상대적 표현 사용 (단순 나열 금지)

**실패 처리:**
- 자기 검증 실패 → 해당 섹션 재작성 (최대 1회)

---

#### Step 6: 문서 생성

**처리 주체:** 스크립트 (`generate_report.py`)

**사전 처리 — 출력 폴더 생성:**
- 실행 시점의 날짜(YYYYMMDD)와 기업명으로 폴더명 결정
- 폴더가 없으면 자동 생성 (`os.makedirs(..., exist_ok=True)`)
- 이후 모든 산출물을 해당 폴더 하위에 저장

**재무 데이터 Word (.docx) — `financials_{날짜}_{기업명}.docx`:**
- `financials_{날짜}_{기업명}.json`의 수치 데이터를 Word 표 형식으로 변환
- 연도별 재무제표 3종(손익/재무상태/현금흐름) + 파생 지표 테이블 포함
- 경쟁사 데이터가 있는 경우 비교 테이블 추가 시트 형태로 구성
- 종합 리포트 에이전트가 원시 수치를 참조할 때 활용

**마크다운 리포트 (.md) — `report_{날짜}_{기업명}.md`:**
- Step 5 분석 텍스트 + 차트 이미지 인라인 삽입 (`![](charts/...png)`)
- `./{날짜}_{기업명}/report_{날짜}_{기업명}.md` 저장

**Word 리포트 (.docx) — `report_{날짜}_{기업명}.docx`:**
- `docx` npm 라이브러리 사용 (`generate_report_docx.js`)
- Python에서 `subprocess.run(['node', 'generate_report_docx.js', ...])` 로 호출 — Node.js 런타임 설치 필수
- 차트 이미지를 `ImageRun`으로 문서에 삽입
- 표지 (기업명, 분석일자, 분석 구간 명시) / 목차 / 본문 구조 포함
- 표지 디자인: 브랜딩 없는 표준 형식 (로고 삽입 불필요)
- `./{날짜}_{기업명}/report_{날짜}_{기업명}.docx` 저장

**완료 알림:** CLI 출력만 (터미널에 완료 메시지 + 출력 파일 경로 목록 표시; Telegram 알림 미구현)

**성공 기준:**
- 산출물 파일 3종 모두 존재 (financials.docx, report.md, report.docx)
- 두 docx 파일 유효성 검증 통과 (`validate.py`)

**docx 검증 수준:** 경량 검증만 수행 — 파일 존재 확인 + `python-docx`의 `Document()` 로드 성공 여부. 콘텐츠 누락 검증은 미수행.

**실패 처리:**
- docx 생성 실패 → md만 최종 산출, 오류 로그 기록 후 사용자에게 안내
- financials.docx 생성 실패 → json만 유지, 스킵 + 로그 기록 (리포트 생성은 계속 진행)

## 4. 설계 결정 근거 (주요 판단 기록)

| 결정 항목 | 선택 | 근거 |
|----------|------|------|
| 단일 vs 멀티 에이전트 | 단일 에이전트 | 순차 워크플로우 + 분석 컨텍스트 연속성 필요 |
| 시각화 라이브러리 | matplotlib 전용 (정적 PNG) | docx ImageRun 삽입 가능, 고해상도 유지, plotly 불필요 |
| 차트 스타일 | 한국형 (대비색, 두꺼운 테두리) | 주 사용자가 국내 애널리스트/투자자 — FnGuide/KIS 스타일 친숙도 |
| 한글 폰트 처리 | generate_charts.py에 rcParams 직접 포함 | 누락 시 차트 레이블 깨짐 방지, 실행 환경 독립적 폰트 설정 |
| 리포트 언어 | 한국어 본문 + 핵심 지표명 영문 병기 | 전문 투자자 사용자 + 글로벌 자료 참조 편의성 |
| 수치 단위 | 조원 (소수점 1자리) | 대형사 애널리스트 보고서 관행, 가독성 향상 |
| DART 단위 인식 | XBRL 메타데이터 자동 판별 | DART 공시마다 단위 표기 방식 상이 — 하드코딩 위험 |
| dart_raw JSON | 미저장 (간소화) | 디버깅 용도였으나 불필요 — financials JSON이 재처리 기준 역할 |
| 데이터 전달 | 파일 기반 (`./{날짜}_{기업명}/*.json`) | 재무 데이터 양이 크고 경쟁사 루프에서 재사용 |
| 에이전트 간 통신 | 출력 폴더 경로 공유 | 종합 리포트 에이전트가 파일 직접 읽기 — 구조 단순 |
| 출력 폴더 구조 | `./{날짜}_{기업명}/` 동적 생성 | 실행 이력이 날짜별로 분리되어 관리 편의성 향상 |
| financials.docx 추가 | JSON + Word 이중 산출 | 종합 리포트 에이전트의 수치 참조 + 사람 검토 모두 지원 |
| Node.js docx 호출 | Python subprocess.run(['node', ...]) | 기존 docx npm 라이브러리 유지 — python-docx로 전환 없음 |
| 완료 알림 | CLI 출력만 | 현 단계에서 외부 알림 불필요, Telegram 연동은 미구현 |
| 연결/별도 우선순위 | 연결 우선 | 그룹 실체 파악에 연결 기준이 더 적합 |
| Red Flag 판단 방식 | LLM 자율 판단 (임계값은 참조 기준점만) | 업종 특성을 기계적 임계값으로 커버 불가 — LLM 컨텍스트 기반 판단이 오분류 최소화 |
| 업종 평균 비교 | 미구현 (v1 범위 외) | 구현 복잡도 대비 사용자 수요 낮음 |
| 경쟁사 자동 추천 | 미구현 | 사용자가 직접 입력 — 잘못된 경쟁사 선정 위험 방지 |
