# 최종 기업분석 종합 리포트 Agent 설계서

> **문서 목적**: Claude Code에서 구현 시 참조할 계획서  
> **역할**: 5개 서브에이전트 산출물을 통합하여 최종 기업분석 리포트 생성  
> **필수 포함**: 비즈니스모델 · 실적 · 밸류에이션 + 산업·리포트·뉴스 기반 전망 시나리오 + 주가 전망  
> **출력 폴더**: 기업별 통합 산출물 폴더 (`C:/claude/stock/{기업명}/{날짜}/final/`)

---

## 1. 작업 컨텍스트 문서

### 1.1 배경 및 목적

5개 서브에이전트가 각각 생산한 1차 결과물을 **하나의 일관된 기업분석 리포트**로 통합한다. 개별 에이전트는 각자의 시각(재무·증권사·뉴스·산업·밸류에이션)에서 독립적으로 분석했으나, 이 에이전트는 그 결과들이 **서로 어떻게 연결되고 강화하거나 충돌하는지**를 교차 분석하여 투자 판단에 쓸 수 있는 최종 관점을 도출한다.

**이 에이전트가 답하는 핵심 질문:**
- 5개 시각을 종합했을 때 이 기업의 현재 상태를 한마디로 어떻게 표현할 수 있는가?
- 향후 주가에 영향을 줄 핵심 변수는 무엇이며, 시나리오별 주가 범위는 어디인가?
- 지금 이 기업에 대해 투자자가 알아야 할 가장 중요한 것은 무엇인가?

### 1.2 입력 산출물 정의 (5개 에이전트 출력)

| 에이전트 | 핵심 입력 파일 | 사용 목적 |
|---------|--------------|----------|
| **①DART** | `financials_{날짜}_{기업명}.json` | 실적 추이·재무 체력·Red Flag |
| | `report_{날짜}_{기업명}.docx` | 재무 분석 서술 참조 |
| **②Telegram** | `analysis_{날짜}_{기업명}.json` | 증권사 투자의견·목표주가·Best/Worst Case |
| | `report_{날짜}_{기업명}.md` | 긍정/부정 논거 참조 |
| **③News** | `analysis_{날짜}_{기업명}.json` | 긍정·부정 사건·미래 추진 계획 |
| | `report_{날짜}_{기업명}.md` | 사건 타임라인·패턴 참조 |
| **④Industry** | `analysis_{날짜}_{기업명}.json` | 산업 시나리오(단기·중기)·밸류체인 위치 |
| | `report_{날짜}_{기업명}.md` | 산업 방향성 서술 참조 |
| **⑤Valuation** | `val_results_{날짜}_{기업명}.json` | 6종 밸류에이션 적정가 범위 |
| | `biz_model_{날짜}_{기업명}.json` | Price·Quantity·Cost 구조 |
| | `disclosures_{날짜}_{기업명}.json` | 주요 공시 이벤트 |
| | `val_inputs_{날짜}_{기업명}.json` | WACC·성장률 가정 |

> **⚠ 출력 형식 불일치 주의:** 5개 에이전트는 독립 설계되었으므로 JSON 키 이름·단위·구조가 에이전트마다 다를 수 있다. `load_and_normalize.py`는 에이전트별 파싱 로직을 분리 구현하여 공통 요약 딕셔너리로 변환해야 한다. 새로운 에이전트 출력 형식이 생길 때마다 이 스크립트도 함께 업데이트해야 한다.

### 1.3 출력 정의

| 구분 | 항목 | 경로 |
|------|------|------|
| **출력** | 출력 폴더 | `C:/claude/stock/{기업명}/{날짜}/final/` |
| **출력** | 통합 분석 JSON | `C:/claude/stock/{기업명}/{날짜}/final/integrated_{날짜}_{기업명}.json` |
| **출력** | 최종 리포트 마크다운 | `C:/claude/stock/{기업명}/{날짜}/final/report_{날짜}_{기업명}.md` |
| **출력** | 최종 리포트 Word | `C:/claude/stock/{기업명}/{날짜}/final/report_{날짜}_{기업명}.docx` |

### 1.4 최종 리포트 7대 섹션

| 섹션 | 내용 요약 |
|------|----------|
| **Executive Summary** | 기업 현황 한 페이지 요약, 핵심 투자 포인트 3~5개 |
| **비즈니스모델 분석** | Price·Quantity·Cost 구조, Moat, 수익 지속성 |
| **재무 실적 분석** | 10년 추이, 핵심 지표, Red Flag 여부 |
| **산업·시장 환경** | 산업 포지션, 단기·중기 방향성, 수급 사이클 |
| **증권사·뉴스 종합** | Sell-side 컨센서스, 주요 사건, 미래 추진 계획 |
| **밸류에이션 종합** | 6종 적정가, 현재 주가 위치, 고/저평가 판단 |
| **투자 시나리오 및 주가 전망** | Positive·Base·Negative 시나리오 + 주가 범위 |

### 1.5 주요 제약조건

- 입력 파일 일부가 없는 경우 해당 에이전트 분석 없이 나머지로 진행, 리포트에 데이터 부재 명시
- 5개 에이전트 간 수치 충돌 시(예: DART 실적 vs 텔레그램 추정치 불일치) → 출처를 분리 기술, LLM 임의 조정 금지
- **주가 전망 범위 규칙:**
  - Base·Negative Case: `val_results fair_value_range` 내에서만 제시
  - Positive Case: `fair_value_range.high`를 초과할 수 있으나 상단 한계는 **Telegram TP 최고치**로 제한
  - 현재 주가 > `fair_value_range.high`인 경우: 모든 시나리오가 하방을 가리킴을 명시("현재 주가 고평가 구간 — 모든 시나리오에서 하방 압력")
- 투자 권유 표현 금지 — 근거 기반 시나리오 제시만 허용 (금지 표현 목록은 `self_check_list.md` 참조)
- 리포트 분량: 섹션 7(시나리오·주가 전망)을 핵심으로 우선 충실히 작성한 후 분량 조정
- 5개 에이전트 JSON 출력 형식 불일치 → `load_and_normalize.py`에서 에이전트별 파싱 로직 분리 구현
- 독자 대상: 개인 투자자. 전문 금융 용어(WACC, EV/EBITDA, FCF 등)는 별도 설명 없이 사용

### 1.6 용어 정의

| 용어 | 정의 |
|------|------|
| 신호 정합성 | 5개 에이전트의 분석 방향이 일치하거나 충돌하는 정도 |
| 핵심 투자 포인트 | 투자 판단에 가장 큰 영향을 미치는 3~5개 요인 |
| 컨센서스 온도 | 증권사 Buy/Hold/Sell 분포 + 뉴스 긍정·부정 비율의 종합 방향 |
| 주가 전망 범위 | 밸류에이션 결과 기반 12개월 목표 주가 하단·중간·상단 |

## 2. 워크플로우 정의

### 2.1 사전 조건 확인

에이전트 시작 전 입력 파일 존재 여부를 스크립트로 검증한다.

```
[입력 파일 존재 확인]
        │
        ▼
필수 파일 (없으면 에스컬레이션):
  - C:/claude/stock/{기업명}/{날짜}/financial/financials_{날짜}_{기업명}.json        ← DART
  - C:/claude/stock/{기업명}/{날짜}/valuation/val_results_{날짜}_{기업명}.json       ← Valuation

선택 파일 (없으면 해당 섹션 "데이터 없음" 처리):
  - C:/claude/stock/{기업명}/{날짜}/telegram/analysis_{날짜}_{기업명}.json
  - C:/claude/stock/{기업명}/{날짜}/news/analysis_{날짜}_{기업명}.json
  - C:/claude/stock/{기업명}/{날짜}/industry/analysis_{날짜}_{기업명}.json
  - C:/claude/stock/{기업명}/{날짜}/valuation/biz_model_{날짜}_{기업명}.json
  - C:/claude/stock/{기업명}/{날짜}/valuation/disclosures_{날짜}_{기업명}.json
```

**Industry agent 누락 시 시나리오 확률 기본값:**
```
Positive: 30% / Base: 50% / Negative: 20%
```
리포트에 "산업 에이전트 데이터 없음 — 시나리오 확률 기본값 적용" 명시.

### 2.2 전체 흐름

```
[입력: 5개 에이전트 산출물 경로]
        │
        ▼
[Step 0] 출력 폴더 생성 + 입력 파일 검증
   스크립트: C:/claude/stock/{기업명}/{날짜}/final/ 폴더 생성, 파일 존재 확인, 누락 파일 목록 생성
        │
        ▼
[Step 1] 데이터 로딩 및 정규화
   스크립트: 5개 에이전트 JSON 로딩 → 통합 컨텍스트 구조로 변환
        │
        ▼
[Step 2] 신호 정합성 분석
   에이전트 직접 수행:
   5개 시각이 같은 방향을 가리키는가, 충돌하는가?
   → 정합 영역 / 충돌 영역 식별
        │
        ▼
[Step 3] 섹션별 LLM 분석 작성
   에이전트 직접 수행: 7대 섹션 순서대로 작성
   (각 섹션은 관련 에이전트 데이터를 교차 참조)
        │
        ▼
[Step 4] 투자 시나리오 및 주가 전망 도출
   에이전트 직접 수행:
   Positive · Base · Negative 시나리오 + 주가 범위 산출
        │
        ▼
[Step 5] Executive Summary 작성
   에이전트 직접 수행:
   전체 분석 완료 후 역순으로 1페이지 요약 작성
        │
        ▼
[Step 6] 자기 검증
   에이전트 직접 수행: 체크리스트 기반 품질 확인
        │
        ▼
[Step 7] 통합 JSON 저장 + 문서 생성
   스크립트: integrated JSON + md + docx 생성
        │
        ▼
[출력: C:/claude/stock/{기업명}/{날짜}/final/ 내 전체 산출물]
```

### 2.3 단계별 상세 정의

---

#### Step 0: 출력 폴더 생성 + 입력 파일 검증

**처리 주체:** 스크립트 (`setup_and_validate.py`)

**수행 작업:**
- `C:/claude/stock/{기업명}/{날짜}/final/` 폴더 생성
- 필수·선택 파일 존재 여부 확인
- 누락 파일 목록을 `missing_inputs.log`에 기록
- 필수 파일 누락 시 → 에스컬레이션 (해당 에이전트 먼저 실행 요청)

**성공 기준:** 필수 파일 2종 모두 존재  
**실패 처리:** 필수 파일 누락 → 즉시 중단, 사용자에게 누락 에이전트 실행 안내

---

#### Step 1: 데이터 로딩 및 정규화

**처리 주체:** 스크립트 (`load_and_normalize.py`)

**수행 작업:**
- 5개 에이전트 JSON 파일 전체 로딩 (에이전트별 파싱 로직 분리 — 키 이름·구조 불일치 대응)
- 날짜 형식 통일, 단위 통일 (억원·조원 혼재 → 억원으로 정규화)
- 에이전트별 핵심 지표를 단일 요약 딕셔너리로 추출

> **컨텍스트 전략:** 요약 딕셔너리는 Step 2(신호 정합성 분석)에 사용. Step 3 각 섹션 작성 시에는 해당 섹션 관련 원본 JSON 파일 전체를 컨텍스트에 재로드하여 정보 손실 없이 서술한다. (예: 섹션 2 작성 시 `biz_model` + `financials` 전체 재로드)

#### Step 2: 신호 정합성 분석

**처리 주체:** 에이전트 직접 수행 (LLM 판단 영역)

**분석 목적:** 5개 에이전트가 같은 방향을 가리키는지, 어디서 충돌하는지 먼저 파악하여 이후 섹션 작성의 뼈대를 잡는다.

**정합성 매트릭스 작성:**

```
                DART   Telegram   News   Industry   Valuation
수익성           ▲       ▲         △       ▲          ▲
성장 모멘텀      △       ▲         ▲       ▲          △
리스크           ▼       △         ▼       △          ▼
현재 가치        -        ▲         -       -          △

▲ 긍정  △ 중립  ▼ 부정  - 해당없음
```

**LLM 판단 항목:**
- **정합 신호** (3개 이상 같은 방향): 높은 신뢰도로 결론에 반영
- **충돌 신호** (에이전트 간 방향 불일치): 원인 추론 후 양쪽 시각을 리포트에 병기
- **공백 신호** (특정 에이전트에만 존재하는 정보): 단독 출처임을 명시

**성공 기준:** 매트릭스 완성, 충돌 영역 원인 추론 포함  
**실패 처리:** 입력 에이전트 2개 이하 → 에스컬레이션 (최소 3개 에이전트 산출물 필요)

---

#### Step 3: 섹션별 LLM 분석 작성

**처리 주체:** 에이전트 직접 수행 (LLM 판단 영역)

각 섹션은 아래 순서대로 작성하며, **해당 섹션에 관련된 에이전트 데이터를 교차 참조**하여 서술한다.

---

**섹션 1 — 기업 개요**
```
- 기업명, 업종, 상장 정보, 주요 사업 영역
- 분석 기준일 및 사용된 에이전트 목록
- 데이터 커버리지 현황 (누락 에이전트 명시)
```

---

**섹션 2 — 비즈니스모델 분석**

*참조: ⑤Valuation `biz_model` + ①DART 사업보고서 요약*

```
2.1 수익 창출 구조
    - Price 축: 주요 제품·서비스 단가 구조, 가격 결정력
    - Quantity 축: 핵심 볼륨 드라이버, 판매량 추이

    - 경쟁사 대비 차별화 요소

2.4 비즈니스모델 강점·약점
    - 뉴스·증권사 시각과 교차 확인하여 강화 또는 보완
```

#### Step 4: 투자 시나리오 및 주가 전망 도출

**처리 주체:** 에이전트 직접 수행 (LLM 판단 영역)

**섹션 7 — 투자 시나리오 및 주가 전망**

*참조: 전 에이전트 데이터 교차 종합*

**시나리오 구성 원칙:**
- 3개 시나리오(Positive·Base·Negative) 각각에 **5개 에이전트 시각이 모두 반영**되어야 함
- 확률은 산업 에이전트 시나리오 확률을 기준으로, 나머지 에이전트 신호로 보정
- Industry agent 누락 시 기본값 Positive 30% / Base 50% / Negative 20% 적용 후 보정

**주가 범위 규칙:**
- **Positive Case 상단**: Telegram TP 최고치 (fair_value_range 초과 허용)
- **Base·Negative Case**: `val_results fair_value_range` 내에서만 제시
- **현재 주가 > fair_value_range.high 인 경우**: 모든 시나리오가 하방임을 명시 ("현재 주가 고평가 구간 — 모든 시나리오에서 하방 압력")

**시나리오 확률 표시 형식 (보정 근거 본문 직접 삽입):**
```
예: Positive 40% (Industry 기준값 35%에서,
    DART FCF 회복 신호 +3%p,
    Telegram Buy 비율 우세 +2%p 보정)
```
보정은 +-15%p 이내로 제한하며 근거 없는 보정 금지. 보정 방향과 수치는 리포트 7.1 각 시나리오 박스 아래에 명시한다.

```
7.1 시나리오별 전제 조건 및 주가 전망

┌─────────────────────────────────────────────────────────────────────┐
│ Positive Case (확률: X%)                                            │
├─────────────────────────────────────────────────────────────────────┤
│ [전제 조건]                                                          │
│  - 재무: FCF 회복, 이익률 개선                  ← DART              │
│  - 산업: 반도체 업사이클 가속, 수요 강세        ← Industry          │
│  - 촉매: HBM4 양산 성공, 엔비디아 추가 수주     ← News + Telegram   │
│  - 공시: 자사주 매입 발표, 대규모 수주 공시     ← Valuation         │
│                                                                     │
│ [예상 실적]  매출 +15~20% / 영업이익률 +3~5%p                       │
│ [주가 전망]  {하단}원 ~ {상단}원 (현재주가 대비 +X%)                │
│ [핵심 모니터링] 이 시나리오의 진행을 확인하는 선행 지표             │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ Base Case (확률: Y%)                                                │
├─────────────────────────────────────────────────────────────────────┤
│ [전제 조건]                                                          │
│  - 재무: 현재 이익률 수준 유지                  ← DART              │
│  - 산업: 완만한 회복, 현재 추세 지속            ← Industry          │
│  - 촉매: 기존 계획대로 진행, 서프라이즈 없음    ← News + Telegram   │
│  - 공시: 특이 이벤트 없음                       ← Valuation         │
│                                                                     │
│ [예상 실적]  매출 +8~12% / 영업이익률 현 수준 유지                  │
│ [주가 전망]  {하단}원 ~ {상단}원 (현재주가 대비 ±X%)               │
│ [핵심 모니터링] Base Case 이탈 신호 (위/아래 방향)                  │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ Negative Case (확률: Z%)                                            │
├─────────────────────────────────────────────────────────────────────┤
│ [전제 조건]                                                          │
│  - 재무: FCF 악화, Red Flag 현실화              ← DART              │
│  - 산업: 업사이클 지연, 중국 공급 과잉 심화     ← Industry          │
│  - 촉매: 핵심 고객사 이탈, 소송 패소            ← News + Telegram   │
│  - 공시: 유상증자, 대규모 손상차손              ← Valuation         │
│                                                                     │
│ [예상 실적]  매출 보합~-5% / 영업이익률 -3~5%p 하락                 │
│ [주가 전망]  {하단}원 ~ {상단}원 (현재주가 대비 -X%)                │
│ [핵심 모니터링] 이 시나리오 진입 신호 (조기 경보 지표)              │
└─────────────────────────────────────────────────────────────────────┘

   (X + Y + Z = 100%)
```

**7.2 시나리오 간 전환 신호 (Trigger Watch)**
```

- Base → Negative 하향 신호: {구체적 지표 또는 이벤트}
- Negative → Base 상향 신호: {구체적 지표 또는 이벤트}
```

**7.3 핵심 투자 포인트 (Key Takeaways)**
```
- 가장 중요한 기회 요인 (1~3개)
- 가장 주의해야 할 리스크 (1~3개)
- 향후 3~6개월 내 확인해야 할 핵심 이벤트 일정
```

### 3.4 에이전트 구조

**단일 에이전트** 구조 채택

**근거:** 7개 섹션이 서로 참조 관계에 있고(비즈니스모델 → 밸류에이션 가정, 실적 → 시나리오 등), 신호 정합성 분석 결과가 모든 섹션 작성의 맥락이 됨. 전체 컨텍스트를 유지해야 일관된 서술이 가능.

- Step 3 각 섹션 작성 시: 해당 섹션 관련 원본 JSON 전체를 재로드 (정보 손실 방지)
- 섹션 완성 직후 `report_{날짜}_{기업명}.md`에 즉시 Append (컨텍스트 유실 대비)
